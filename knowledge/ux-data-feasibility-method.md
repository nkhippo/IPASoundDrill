# データ現実的な UI/UX 検討・レビュー法（横展開モデル）

Claude / Claude Design に UI/UX を検討・レビューさせるときの、駄作を防ぐ標準手法。**IPASoundDrill の 2026-07 CD-parity 案件をモデル**にしている（記載例は `examples/`）。

## 中心原理
デザインの品質は **「実データ・実コードの実現性を、設計の前に棚卸ししたか」** でほぼ決まる。
- **Claude Design（ビジュアル生成）** は repo のデータ/コードを見られない → 存在しないフィールド・被覆率不足・i18n 漏れを平気で綺麗に描く。
- **ClaudeCode（repo アクセス）** が「実現性の層」を担うと品質が跳ねる。

| 層 | 担当 | 役割 |
|---|---|---|
| 実現性・データ | ClaudeCode | フィールド有無・被覆率%・派生可否・i18n・空状態 |
| ビジュアル・IA | Claude Design | レイアウト/意匠/インタラクションの完成度 |
| レビュー | ClaudeCode ＋ design 系 skill | 主張≠実装 / 冗長 / a11y / コピー |

## パイプライン（4ステップ・ループ）
1. **棚卸し**（設計の前）: `ux-brief` skill。フィールド・被覆率%・派生可否・「データに無いもの」を実測。
2. **brief 作成**: 5節テンプレ（`.claude/skills/ux-brief/references/brief-template.md`）。§A はコード側が埋める。
3. **生成**: Claude Design が brief に忠実に描く。
4. **査読**: `ux-review` skill でデータ/コードに突合。→ 1へループ。

- 入力＝案「テンプレを CD へ」＋「ClaudeCode が整形」の合わせ技（§A を必ず ClaudeCode が埋める）。
- 出力＝案「ClaudeCode の design 系 skill で Rv」。生成は CD、査読は ClaudeCode。

## 駄作を生む典型パターン（このケースで実際に検出）
- **主張≠実装**: 表示するが未実装（例: streak「N日連続」が未追跡。placeholder `7`/`312` のハードコード）。
- **フィールド取り違え**: `pat` を見て「無い」と誤判定 → 実は `pattern`（27%）。**名前を実データで確認**。
- **i18n 漏れ**: 品詞 `pos` が日本語格納。対応表未収載 19% が生の日本語で他言語ユーザーに露出。
- **冗長**: `GA=RP` バッジ＋中身同一の RP 行の二重表示。
- **自動表示のノイズ**: 要注意音の元 `t:1` が 47音中23音 → 平均2.7音/語を列挙 = 情報が雑多（＝「白地にダサい」の内容側原因）。
- **宝の持ち腐れ**: `respell`(98%)・`ga_rp_same_reason`(100%) がロード済なのに未表示。

## 伝え方のコツ（Claude / Claude Design へ）
- 「いい感じに」ではなく、**§A に被覆率%と“無いもの”を数値で**渡す。
- 「この画面の主目的は1つ」「主役1・補助2まで」など**情報量の上限**を明示（雑多防止）。
- レビュー依頼は「綺麗か」でなく **「このデータで成立するか・空時どう見えるか・重複は無いか」** と聞く。
