## 目的

IPA Sound Drill が **絶対に採用しない設計パターン** を明示。Claude Design が "学習アプリのベストプラクティス" として提案してくる可能性が高い要素を、事前に NG リスト化して排除する。

「何を作るか」より「何を作らないか」を先に決めることで、プロダクトの軸がぶれない。

## このドキュメントの位置づけ

- **性質**: Claude 主導のドラフト。Naoya さんが各項目の妥当性を判断
- **完成度目標**: Phase 1 起動前に完成、Claude Design ブリーフ §4 "What we're NOT doing" で参照
- **参照される場面**:
  - Claude Design ブリーフの §4 "What we're NOT doing"
  - 新機能提案の判断
  - Cursor 実装で "こういう UI もいいかも" 提案時のブレーキ

## Anti-pattern カテゴリ

| カテゴリ | 対象 | 参照原則 |
|---|---|---|
| A. Motivational | 学習動機の外発化を招く要素 | 原則 4 (禁欲的達成)、原則 7 (所有物) |
| B. Character | プロダクトの声を擬人化する要素 | Voice & Tone (静かな師範) |
| C. Visual | プロダクトの視覚方向性を損なう要素 | 原則 4、Sensory Design |
| D. Interaction | 学習者の自律性を損なう要素 | 原則 7、原則 2 (意思決定回数減) |
| E. Language | Voice & Tone の Taboo List 由来 | Voice-and-tone.md |
| F. Feature | プロダクトのスコープに合わない機能 | 原則 1 (メタ言語尊重) |

## Category A: Motivational Anti-patterns

### A-1: 連続日数 / Streak プレッシャー

- **やらないこと**: 「7 日連続学習中!」「Streak を失いたくないなら今日も学習を!」的な催促
- **なぜ**: 学習の内発的動機を "連続を切りたくない" 恐怖に置き換える。学習者が旅行や病気で 1 日休むと "全て失った" 気分になる
- **競合の失敗例**: Duolingo (streak notification の攻撃性)
- **代替案**: 学習履歴は "自分の資産" として静かに表示、催促しない (原則 7)

### A-2: XP / Level up / Badge 通知

- **やらないこと**: 「10 XP 獲得!」「Level 5 に到達!」「新しいバッジ: Grammar Master!」的な演出
- **なぜ**: ゲーム的な数値化は学習の内容から注意を逸らす。ペルソナ P-1, P-2 は特に嫌悪
- **競合の失敗例**: Duolingo, Memrise
- **代替案**: 進捗は "現在地" として静かに提示 (メーター、リスト)、報酬化しない

### A-3: 連続正解時のファンファーレ / 紙吹雪

- **やらないこと**: 5 問連続正解で 🎉 音声 + 視覚エフェクト
- **なぜ**: 学習者の内発的満足を邪魔する。集中モードを崩す。P-1 の「発音が綺麗と言われる」美的成功と対比して薄っぺらい
- **競合の失敗例**: Duolingo, Kahoot
- **代替案**: 静かに次の問題へ (原則 4)

### A-4: リーダーボード / 他者比較

- **やらないこと**: 「あなたの週の順位: 234 位 (前週比 +12)」的な他者比較
- **なぜ**: 学習は個人の営み。他者比較は本来の学習動機を損なう。IPA Sound Drill のペルソナは全員 "自分と対話する" スタイル
- **競合の失敗例**: Duolingo Leaderboard, Kahoot
- **代替案**: 実装しない。自分の履歴のみ表示

### A-5: 「今日の目標を達成しよう!」プッシュ

- **やらないこと**: プッシュ通知や UI ポップアップで学習を促す
- **なぜ**: 学習者に "指示" するのはプロダクトの立場ではない。原則 7 (所有物 vs 監視物) 違反
- **競合の失敗例**: ほぼ全ての学習アプリ
- **代替案**: プッシュ通知の実装自体を Track A では見送る (Track B でも慎重)

## Category B: Character Anti-patterns

### B-1: AI キャラクター / マスコット

- **やらないこと**: 「こんにちは、IPA くん!」「音声の妖精エコーです!」的なキャラクター登場
- **なぜ**: プロダクトの声 (Voice) が擬人化に吸い取られる。P-1 の "深い話がしたい" 動機と反する
- **競合の失敗例**: Duolingo (Duo the owl), ELSA Speak (ELSA character)
- **代替案**: プロダクトは "静かな師範" として無形の存在に留める

### B-2: イラスト化された "先生" / "コーチ"

- **やらないこと**: Reveal 画面に "先生キャラ" のイラストが「よくできました!」と話しかける
- **なぜ**: 学習の主体は自分。プロダクトが "教える立場" として振る舞うのは不適切
- **競合の失敗例**: Rocket Languages, Rosetta Stone (一部)
- **代替案**: 情報のみ提示、判断は学習者に委ねる

### B-3: 音声チャットボット / 対話 UI

- **やらないこと**: 「今日は何を勉強しますか?」と AI が対話で学習を導く UI
- **なぜ**: 音声認識は音の学習には邪魔 (自分の発音を評価される緊張)。プロダクトの声が擬人化される
- **競合の失敗例**: ELSA Speak, Speechling, Cambly AI
- **代替案**: 選択式・タイプ入力のみ、AI 発話は使わない

## Category C: Visual Anti-patterns

### C-1: 明るすぎる原色 / ネオンカラー

- **やらないこと**: 学習アプリ的な明るい赤・黄・緑を UI に多用
- **なぜ**: 学習の集中を妨げる。Naoya さんの美意識 (静けさ、Notion 的) に反する
- **競合の失敗例**: Duolingo (green), Rocket Languages (bright combinations)
- **代替案**: 現行の `--signal: #0C7C7E` (teal) を基調、Cluster 2 で刷新するが方向性は静けさ

### C-2: 過剰な影 / グラデーション / neumorphism

- **やらないこと**: 3D 風の影、ネオモルフィズム、intense gradient
- **なぜ**: 視覚ノイズが多い、静けさを損なう、モバイルパフォーマンスにも悪影響
- **競合の失敗例**: 一部の実験的 UI (2019-2020 のトレンド)
- **代替案**: Flat design、subtle border、必要な場所のみ minimal shadow

### C-3: カートゥーン風イラスト

- **やらないこと**: 学習トピックに関連するカートゥーンイラストを配置
- **なぜ**: 大人の学習者 (P-1, P-2) は "子供扱い" と感じる。P-5 (若年層) でも Instagram 世代は "ダサい" と受け取る
- **競合の失敗例**: Babbel (一部)、Rosetta Stone
- **代替案**: 抽象的な形、タイポグラフィ主体、必要なら本物のイラストは art quality で

### C-4: 過剰な絵文字

- **やらないこと**: UI 全体に絵文字を散りばめる (🎯 目標 🎉 達成 🔥 連続 等)
- **なぜ**: プロダクトのトーンが軽薄になる。Voice & Tone Taboo List にも記載
- **競合の失敗例**: Duolingo, Memrise
- **代替案**: 絵文字は使わない。必要ならアイコンフォント (Lucide 等) で

### C-5: 過剰なアニメーション / モーション

- **やらないこと**: 画面遷移で回転・拡大縮小・派手な motion
- **なぜ**: 集中を妨げる、モバイルでの操作感が重く感じる、Sensory Design の "静けさ" 原則違反
- **競合の失敗例**: 一部の "モダン" 学習アプリ
- **代替案**: フェード 150-200ms、slide は避ける、reduced-motion 対応

## Category D: Interaction Anti-patterns

### D-1: タイマー / カウントダウン

- **やらないこと**: 「あと 10 秒で回答!」「1 日 1 レッスンの制限!」的な時間圧迫
- **なぜ**: 音の学習は焦らせると逆効果。落ち着いて聞く時間が必要
- **競合の失敗例**: Duolingo (時間制限モード)、Kahoot
- **代替案**: 学習者のペースに委ねる、時間表示はしない

### D-2: 強制チュートリアル

- **やらないこと**: 初回訪問時に 20 スライドのチュートリアルを強制、スキップ不可
- **なぜ**: P-1, P-2 は "早く始めたい" 派、押し付けの学習前学習を嫌う
- **競合の失敗例**: Rosetta Stone (長いオンボーディング), 一部の SaaS
- **代替案**: 3 スライド程度のショートオンボーディング + いつでもスキップ可 (UX 課題 C-7)

### D-3: 選択肢の過剰 (choice paralysis)

- **やらないこと**: Setup 画面に 12 パラメータを同時に見せる (現状)
- **なぜ**: 原則 2 (意思決定回数を減らす) 違反。C-1 で強化
- **競合の失敗例**: Anki の初期設定
- **代替案**: 目的カードから入る (N-3)、詳細設定は折りたたむ

### D-4: 誤操作誘発 UI

- **やらないこと**: 大事なボタン (Exit, Delete) と一般ボタン (Next) を隣接配置
- **なぜ**: 誤タップでセッションを失うと学習体験が破壊される
- **競合の失敗例**: 一部のミニマリズム UI
- **代替案**: 破壊的操作は Confirmation modal で確認 (現行の Exit modal は保持)

### D-5: 学習途中の広告 / ポップアップ

- **やらないこと**: セッション中に広告や課金誘導を挟む
- **なぜ**: 集中モードの破壊、プロダクトへの信頼喪失
- **競合の失敗例**: Duolingo Hearts, 多くの無料学習アプリ
- **代替案**: Track A では広告なし、Track B で monetization を検討する際も学習フローに介入しない

## Category E: Language Anti-patterns (Voice-and-tone Taboo List 由来)

- **E-1: 「マスター」「攻略」「完璧」「ネイティブ」等の禁止語彙** (Voice-and-tone.md §Vocabulary Preferences 参照)
- **E-2: 「頑張ろう!」「がんばれ!」等の努力煽り** (学習者の自律性を損なう)
- **E-3: 「〜しちゃう」等のカジュアル過ぎる語尾** (プロダクトの距離感を損なう)
- **E-4: 「AI」「AI 発音矯正」等のテクノロジーアピール** (プロダクトの声を擬人化に近づける)

詳細は `docs/design/voice-and-tone.md § Taboo List` を参照。

## Category F: Feature Anti-patterns (プロダクトのスコープに合わない機能)

### F-1: 発音の "スコアリング" (0-100 点評価)

- **やらないこと**: 学習者の発音を録音して "スコア 78/100" と評価する UI
- **なぜ**:
  - Track A は音声認識非対応 (静的 HTML + GAS の制約)
  - 学習者の発音を "点数化" するのは原則 4 (禁欲的達成) 違反
  - P-1 の "美的評価" (綺麗、聞き取りやすい) はスコアで測れない
- **競合の失敗例**: ELSA Speak (核心機能)
- **代替案**: Encode モードで学習者の "推測 IPA" を入力させる (正解との差分のみ静かに提示)

### F-2: ソーシャル機能 (フォロー、コメント、シェア)

- **やらないこと**: 学習履歴を SNS シェア、他の学習者をフォロー、学習ログにコメント
- **なぜ**:
  - 学習は個人の営み (原則 7)
  - Track A のスコープ外 (BE 移管が必要)
  - プライバシー配慮の複雑化
- **競合の失敗例**: Duolingo Friends, Memrise
- **代替案**: Track B でも社交機能は慎重に (もし実装するなら明示的なオプトイン)

### F-3: 課金誘導 / Premium 機能の壁

- **やらないこと**: 「B2 レベルは Premium で!」「1 日 5 問まで、続きは Premium で!」的な壁
- **なぜ**:
  - Track A のスコープ外
  - Naoya の設計哲学と反する (学習は誰でもアクセス可能に)
  - P-3 (フィリピン CS) は高価で即離脱
- **競合の失敗例**: ほぼ全ての商用学習アプリ
- **代替案**: Track A は完全無料。Track B の monetization は Feedback + Donation ベース検討

### F-4: 学習カウンセリング / 個別プランの押し付け

- **やらないこと**: 「あなたの弱点分析」→ 個別学習プランを提示 → プランに従って学習
- **なぜ**:
  - プロダクトが "指導者" になるのは Voice (静かな師範) 違反
  - 現行の focus フィルタで十分 (学習者自身が選ぶ)
  - Naoya の "学習の自律性" 尊重
- **競合の失敗例**: Riiid (AI Tutor), Elsa Pro
- **代替案**: 弱点は自分で気付ける仕組み (weak spots フィルタ、SRS 履歴)

### F-5: 過度な gamification (score, competition, streaks)

- **やらないこと**: 上記 A-1〜A-4 の複合、ゲーム的な学習体験全体
- **なぜ**: プロダクトの根本哲学と反する
- **競合の失敗例**: Duolingo 全体
- **代替案**: 学習体験は "静かなドリル"、達成は自分の内面で

## この規約の使い方

### Claude Design ブリーフでの参照

各 Cluster のブリーフ §4 で:

```
## 4. What we're NOT doing

このプロトタイプで特に排除すべき anti-patterns:
- A-1〜A-5 (すべての motivational anti-patterns)
- B-1, B-2 (character anti-patterns、Reveal 画面での teacher persona の登場)
- C-1 (明るすぎる原色、原則 4 に整合)
- D-3 (選択肢過剰、原則 2 と C-1 課題に整合)
- F-1 (発音スコアリング、Track A では不可能でもあり不要でもある)

このブリーフに特に該当しない:
- D-1 (タイマー、Reveal 画面には元々ない)
- F-2 (ソーシャル、このプロトタイプで扱わない)
```

### 新機能提案の判断

新機能を検討するとき:

1. Category A-F のどれかに該当するか確認
2. 該当する場合、原則的に却下
3. 該当しない場合、product-principles.md との整合を判断

### Cursor 実装時のブレーキ

Cursor が実装中に "こういう UI もいいかも" と提案してきたら:

- Anti-patterns.md に照らして判断
- 該当する場合、Naoya さんが Chat で明示的に却下
- Cursor 実装レポートにその判断を残す

## Naoya さんへの依頼

- **各 anti-pattern の妥当性**: すべて Naoya さんの philosophy に整合するか確認、違和感があれば削除・追加
- **F-3 (課金) の Track B 方針**: Donation ベースの想定で良いか、他のマネタイゼーションを検討するか
- **B-1 の例外はあるか**: マスコットは絶対に無し、しかしイラスト (art) は art quality なら OK か
- **リストの追加**: Naoya さんが "これも避けたい" と思う項目があれば追加
